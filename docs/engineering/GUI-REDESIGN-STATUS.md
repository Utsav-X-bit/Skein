## Changes

- Correct ufw route deletion in the daemon, repair rollback and shell script. Missing-rule handling reads both runner output and error instead of assuming output is embedded in the error.
- Elevate Linux CLI helper calls through pkexec; preserve bootstrap tokens in memory/stdout only. Windows lifecycle uses UAC; unelevated first setup gives explicit elevated-PowerShell guidance rather than moving a token to disk. Status remains unprivileged. Bootstrap 403 guidance distinguishes token/transport mismatch from a role grant.
- Fix the additional GUI elevation root cause: pkexec has no `--action` option. GUI/bootstrap/CLI now use the documented `pkexec <absolute helper> <verb>` grammar. One executable-path-selected polkit policy is admin-only, uncached and denied to inactive/remote sessions; no GUI environment preservation. The packaging gate checks these authorization invariants structurally.
- Add Settings network recovery: same-network rejoin uses the normal daemon join endpoint with confirmation; switching announces self-departure, resets with backup/purge and keep-identity choices, verifies Stop, then offers create/join/import. It never removes another peer. A failed Stop preserves the completed reset and exact backup path; retrying Stop does not repeat reset. No raw endpoint is presented as recovery guidance.
- Verify authoritative OS service state after every lifecycle method, including helper failure and asynchronous transitions. Settings retains service controls if config is unavailable and refreshes after success or failure. Rotation/reset use the same verified lifecycle methods.
- Add NSIS and PowerShell running-desktop guards before service/file mutations. Nothing is killed. Correct an existing NSIS string-escaping compile error. Packaging-order checks distinguish executable RMDir statements from comments.
- Set explicit Windows DACLs before path-based operations in access-file, backup, update-state and rollback writers; fix Windows access temp-file placement. Preserve Unix executable modes when copying binaries. Native testing subsequently reproduced a separate directory-inheritance defect: hardening a directory with non-inheritable ACEs stripped its existing lock file's inherited access. Directory ACEs now inherit to files/subdirectories; the four-path native regression fails before the fix and passes afterward.
- Replace cross-process lock-test sleep/poll synchronization with a child stdout handshake and process wait. Fix an API authentication fixture to grant mutation explicitly; remove a nondeterministic map-order assertion and obsolete forwarding/binding-availability tests.
- Regenerate bindings and replace obsolete availability shims with actual generated methods/types. Setup has five methods before and after: `Reset` was removed and `Rejoin` added. `ResetWithPurge` now returns structured partial completion. Other relevant method counts remain Service 8, Peer 4, Invite 3, Update 4; generator reports 12 services / 46 methods / 29 models.
- README now has exactly two installation methods: complete Windows setup artifact, and platform-separated source builds. Prerequisites precede the source steps; Linux copies `gui/bin/skein-desktop`; helper installation remains existing-config-only. No installer binary is committed. The source Windows installer now requires and copies `wintun-LICENSE.txt`, pins service registration to its own install directory (`--daemon`), detects the desktop beside `-SourceDir`, and the packaging gate checks the licence payload. README gained the missing `git` prerequisite, arm64 Wintun fetch, exact uninstall commands, the per-user socket-ACL wording, and the Ubuntu 24.04 unprivileged-user-namespace note required by WebKitGTK's sandbox.
- Bootstrap success now hands the bound control listener to the normal daemon instead of closing and rebinding it, so the first client after setup is served by the normal API (no dead-transport window). Post-commit requests are held (5 s), released with 503 on transition failure, and the Unix socket is removed on stop; token/uid/SID binding and the transport gate are untouched.
- `reset --keep-identity` now actually reuses the retained key: mint validates and allows it, init/join reuse it (join derives the overlay from the retained ID), import keeps it over a conflicting source key, and rollback never deletes it.
- Fresh-install bootstrap admits the invoking uid/SID to the control socket with the least role (read) before starting the service, so a Linux user outside the `skein` group and a filtered Windows admin token can post the token they were given; existing roles are preserved and a missing `setfacl` fails early with a clear message.
- A dismissed pkexec prompt now reads as approval guidance instead of `exit status 126`, through one shared formatter used by onboarding and Settings.

## Remaining items

1. Owner-approved deferral: invitation expiry, active-invite inventory and invite-use attribution. Network invites contain a reusable secret; UI-only expiry/tracking cannot enforce admission or establish attribution. Generation, QR/copy, snapshot warnings and rotation remain in scope. F-01 per-peer revocation remains deferred.
2. Runtime coverage: the Windows run was a fresh source install (no upgrade path, no NSIS package) and both the Windows and Linux runs were single-node (no peer/relay traffic). The Linux upgrade used the documented source-install path, not a distribution package.
3. Diagnostics paging uses the support-bundle ring rather than the daemon's `next` cursor; the service still drops `next`.
4. A partial-reset Retry-stop panel is component-scoped; navigating away loses the inline panel (the backup file remains).
5. Carried protocol observations: a departure tombstone delays reconnection up to 180 s (the UI now says “waiting for peers” instead of claiming the mesh resumed), and the Windows peer-list asymmetry remains undiagnosed.
6. Documentation acceptance remains bounded: the public clone/prerequisites/installs were executed in Phase 0, but Linux distribution packages were not built and native Windows packaging was not re-run.

The redesign's visual/UX audit was code- and screenshot-level on Linux; a full multi-platform visual audit and the deferred invitation protocol work remain future work.
